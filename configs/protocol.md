## Метод и изменение страницы

Сравниваются static (исходный порядок) и semantic (семантическая перестановка). Подключаемый adapt.js отправляет историю просмотров API на Node.js. Бэкенд усредняет нормированные векторы описаний последних 10 просмотренных блоков и сортирует все семь блоков по косинусной близости к этому профилю. При равных оценках остаётся исходный порядок, без истории перестановок нет.

Меняется только порядок: содержимое и раскрытие блоков сохраняются. Перестановка применяется перед следующей задачей, DOM-узлы сохраняются. Ошибка API оставляет текущий порядок. Для каждого прогона создаётся отдельный сеанс с пустой историей.

Модель, ONNX-файл, ревизия, версии Node.js и Transformers.js закреплены в JSON. Дообучения и внешних API нет. В обычной работе просмотр фиксируется после секунды, в течение которой середина окна находится внутри блока. В измерениях история задаётся программно; сбор браузерных событий проверяется отдельно.

## Задачи и показатели

Каждая задача начинается с scrollTop=0 и требует двух блоков в заранее заданном порядке. Начало каждого блока выравнивается по верху окна с ограничением доступной прокрутки страницы. Суммируются абсолютные изменения фактического scrollTop. Деление на высоту окна даёт основной показатель scroll_distance_viewports. Цели и правильные ответы известны измерителю, но не методу. Для каждого целевого блока задаётся действие и ожидаемый ответ по данным страницы: чтение значения либо проверка функции, например расчёта. Успех требует совпадения обоих ответов и доступности функций. После задачи в историю добавляются два использованных блока; эти события одинаковы для пары вариантов.

D = прокрутка static − прокрутка semantic. Для каждого сценария H0: E(D)≤0.5 экрана; H1: E(D)>0.5 экрана. Авторский практический порог 0.5 выбран заранее. Преимущество подтверждается при нижней границе парного 95% доверительного интервала выше 0.5 и без снижения успешности. Дополнительно записываются ошибки, клики, техническое время, задержка API и CPU/RAM; загрузка модели отдельно.

## План запусков

2 варианта × 2 сценария × 10 seed (4210–4219) = 40 основных прогонов. Stable: 80% задач используют выбранную пару блоков, в остальных задачах равновероятно выбирается пара разных блоков из оставшихся пяти; shift меняет пару на непересекающуюся после 12 из 24 измеряемых задач. Начальная история содержит 10 просмотров, сформированных тем же генератором. Пять пробных задач прогревают программу; затем состояние очищается, загружается история и начинаются измерения.

Дополнительно 5 A/A-пар static, 10 прогонов, и по одной проверке без истории для двух вариантов. Всего 52 прогона. Порядок перемешивается seed 4210. Второй полный запуск пересоздаёт контейнеры/браузер и состояние API, повторяет планы. Серии не объединяются в n=20.

## Калибровка и анализ

Окно 1280×900. Тестовая страница высотой не менее 2700 пикселей имеет точки на 0, 900 и 1800. Переход от начала к второй точке даёт один экран, последовательный переход начало–вторая–третья два экрана. Допуск один CSS-пиксель. Проверяются reset, пустая история, обработчики и значения после перестановки. Генератор готовит 10000 планов с замером времени; CPU/RAM API и измерителя фиксируются отдельно. В A/A действия и прокрутка совпадают, время оценивается с интервалом; p>.05 не доказывает эквивалентности.

Единица анализа: средняя прокрутка за прогон. По сценарию n=10 пар. Парный процентильный бутстрэп: 5000 перевыборок, seed 4210. Дополнительный точный двусторонний тест меняет знаки разностей всеми 1024 способами; предполагается обменность знаков. Холм по двум p. Этот тест проверяет ноль, а не практический порог. Публикуются разности, интервалы, p/скорректированные p и dz либо пропуск. Строятся диаграммы размаха с точками и ECDF времени.

Ошибки сохраняются; уменьшение прокрутки при снижении успешности не признаётся выигрышем. Повреждённый набор сохраняется с причиной, после исправления выполняется новый полный запуск.

Близкие оценки и изменения порядка не скрываются. Планируемые команды: make experiment для полного цикла, make analyze для пересчёта. CI выполняет сборку и калибровку, а не полный эксперимент.

Вывод ограничен технической прокруткой в синтетических задачах. Для оценки удобства и времени поиска людьми нужны участники.
