# План проведения эксперимента

Проект задания 3. SHA256 файла experiment.json: `e7d433fe361e8ffa17e2353fd98cfa24cc55f615e4110d00d1edef0ad9ede804`. Конфигурация, описания блоков, планы и файлы модели фиксируются до основных измерений.

## Объект и методы

К странице отдельной квартиры подключается внешний adapt.js с API на Node.js. Используются семь блоков из experiment.json: планировка и вид на этаже, характеристики, способы покупки, ипотечный калькулятор, преимущества ЖК, преимущества квартиры и похожие квартиры. Начальное расположение и раскрытие задаётся одинаково скриптом для всех методов: первые три раскрыты, остальные свёрнуты. В контроле скрипт не обновляет этот вид по истории. Изменение происходит перед новой задачей. Фиксированный вариант static сохраняет исходный порядок. Частотно-давностный метод recency суммирует веса событий по ID компонента; семантический метод semantic усредняет текстовые представления просмотренных компонентов с теми же весами и ранжирует кандидатов по косинусной близости. Открытие/раскрытие имеют вес 1, сохранение 2; вес уменьшается вдвое за 6 событий. Равные оценки разрешаются исходным порядком. Без истории используется фиксированный порядок.

Клиент adapt.js работает в браузере, его API и модель на Node.js 24.11.0 с Transformers.js 3.8.1. Python 3.12.3 используется только для измерителя и анализа. Зависимости фиксируются в package-lock.json и Python lock-файле, образы и контрольные суммы записаны в runtime конфигурации. Для семи блоков задаются селекторы и обработчики событий; при смене сайта нужна другая настройка.

Модель paraphrase-multilingual-MiniLM-L12-v2, ревизия e8f8c211226b894fcb81acc59f3b34ba3efd5f42, ONNX-файл onnx/model.onnx, fp32, CPU и один поток вычислений, усреднение токенов и нормированные векторы, максимум 128 токенов. Дообучения и внешних API языковых моделей нет. Описания компонентов одинаковы для методов и не содержат будущую цель или метку сценария.

## Гипотеза

Основной показатель: среднее число навигационных кликов до двух инструментов на задачу. Раскрытый инструмент требует 0, свёрнутый 1 клик; возможный итог 0/1/2. Ввод, прокрутка и действия внутри инструмента пишутся отдельно. D = клики фиксированного варианта − клики адаптивного метода для сравнений с контролем, D = клики частотно-давностного метода − клики семантического метода для прямого сравнения методов. Для каждого сравнения/сценария H0: E(D)≤0.5; H1: E(D)>0.5. Порог 0.5 выбран автором как инженерный критерий, не взят из статьи. Практическое преимущество подтверждается при нижней границе парного 95% доверительного интервала бутстрэпа выше 0.5 и без снижения успешности.

## План

Три варианта страницы × четыре сценария (stable/shift/related/uniform) × 10 seed (4210–4219), 120 основных прогонов. Дополнительно 5 A/A-пар static, 10 прогонов, и по одной проверке без истории для трёх вариантов. Итого 133. Порядок прогонов перемешивается с начальным значением генератора (seed) 4210. Второй полный запуск пересоздаёт контейнеры и браузер, очищает историю API, повторяет планы и порядок; результаты серий не объединяются.

На прогон: свежий контекст браузера, отдельный ID сеанса API с пустой историей, 5 технических задач прогрева, очистка истории, 18 начальных и 24 измеряемых задачи в stable/shift/uniform; в related одна измеряемая задача. Stable: 80% задач к горячей паре, остальные из прочих; shift меняет пару на непересекающуюся после 12 измеряемых задач. Uniform выбирает два разных компонента равновероятно. Related использует одну из трёх групп в JSON: в начале нужен первый компонент, затем единственная измеряемая задача требует второй и третий. Последующее запоминание новой пары не входит в эту проверку. Это целевой тест переноса, а не предположение о распределении реальных посетителей.

Эталонные required_components и ожидаемый результат расчёта известны только генератору и измерителю. Метод получает прошлые завершённые события; история пополняется после проверки задачи. Для всех методов одинаковая смысловая последовательность событий; физические DOM-действия и их длительность сохраняются отдельно. Вводы и способ получения результата конкретного инструмента фиксированы до измерений.

## Проверки и анализ

Калибровка проверяет известные пути: 0 кликов к раскрытому инструменту, 1 к свёрнутому и 2 к двум свёрнутым, расчёты, сброс истории, отсутствие будущих событий в истории и стабильность страницы во время действия. Измеряются подготовка 10000 планов, CPU/RAM отдельно для API с моделью и измерителя с браузером, отдельная холодная загрузка весов. A/A сравнивает действия/исходы точно; техническое время описывается с интервалом, p>.05 не доказывает эквивалентность.

Для каждого сценария сравниваются recency/static, semantic/static и semantic/recency. По каждому из 12 сравнений n=10 пар прогонов. Парный процентильный бутстрэп: 5000, seed 4210. Двусторонний точный тест с перестановкой знаков парных разностей: 1024 комбинации, предположение обменности знаков. Поправка Холма по 12 p одного запуска. Этот p проверяет ноль, а не практический порог. Публикуются все разности, интервалы, исходные и скорректированные p и стандартизированный размер эффекта dz либо пропуск. Индивидуальные интервалы не являются одновременными. Диаграммы размаха содержат отдельные прогоны; график накопленной доли завершённых прогонов (ECDF) показывает техническое время. Связь порядка и времени разведочная.

Ошибки и неуспешные задачи сохраняются. Публикуются успешность, действия всех и отдельно успешных задач; преждевременный отказ не засчитывается как экономия. Повреждённый набор не используется для подтверждающего вывода, но сохраняется с причиной; после исправления выполняется новый полный запуск.

В манифест входят HTML/CSS/JS и ответы запросов контрольной страницы, версия adapt.js, настройки селекторов, коммит Git и файл незакоммиченных изменений, образы, Python/библиотеки/Chromium, модель/ревизия/хеши файлов, данные/конфигурация/планы, UTC/seed/метод, CPU/RAM и SHA256 первичных данных. Повторный анализ должен совпасть по действиям точно, по статистике до 1e−12. Допуск оценок модели между средами 1e−6; порядок при близких оценках фиксируется отдельно. Для полного запуска эксперимента предусмотрена команда make experiment, для повторного анализа make analyze. Для автоматической проверки при отправке изменений планируются сборка, pip check и калибровка без полного эксперимента.

Вывод ограничен технической эффективностью при синтетических задачах. Преимущество в реальном выборе жилья или удобстве людей этим протоколом не доказывается.
